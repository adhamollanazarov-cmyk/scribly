# Decisions

One entry per non-obvious decision or new dependency. Newest on top.

| Date | Decision | Why | Agent |
|---|---|---|---|
| 2026-10-12 | Signs: calc drafts carry `positive` (what a positive result means) in the draft and the ledger only, not in the lesson `Calc` contract. Step lint enforces one readable, drawn convention per lesson; eval grading v3 matches a bank `direction` from sign + `positive`. circ-kirchhoff's manual direction check becomes this automatic check | A signed number means nothing without its convention, and the circ-kirchhoff bug (all magnitudes right, directions wrong) needs a machine-checkable direction. Keeping it out of the contract avoids a schema change; the renderer has no use for it yet. Prose direction claims (e.g. in the summary) are still not machine-checked | claude |
| 2026-10-12 | Calc verification adds an absolute tolerance of 1000 × a first-order floating-point rounding bound of the evaluation; a result within it is stored as exactly 0 | A relative tolerance alone can never verify `expected` 0 (cos 90° gives 6e-17). A bound from the evaluation itself, unlike one scaled by the largest input, does not swallow small real results (k·q/r² with tiny q) | claude |
| 2026-10-10 | Eval grading v2 compares signed, rounded displayed results with explicit SI unit conversion and rejects unverified steps. Kirchhoff directions require manual review; historical scores keep their original evidence and carry migration warnings. | Magnitude-only, unit-blind scoring gave false passes. A bounded AST unit parser adds no dependency; numeric checks cannot certify prose/arrow direction. Reserve ledger calc names and primitive/group IDs before streaming, and propagate final validation failure as an SSE error. | codex |
| 2026-10-10 | Lesson generation uses `output_config.format` (structured outputs) with a lean **draft** schema: lesson skeleton typed, one generic draw item with typed `num`/`txt` key-value args; Pydantic + contract models check each item | Measured on Sonnet 5.5: the full typed lesson (and even a flat object of ~70 required properties) returns 400 "compiled grammar is too large"; `$ref`s shrink the budget further, so the schema is inlined. Strict tool use is not an option: Sonnet 5.5 rejects forced `tool_choice` | claude |
| 2026-10-10 | Default `LESSON_THINKING=between_tools`, `LESSON_EFFORT=high` (A/B with adaptive in the eval report) | Sonnet 5.5 rejects `thinking: disabled`; `between_tools` is its no-thinking mode and keeps step 1 fast. Founder chose this with an A/B run | founder |
