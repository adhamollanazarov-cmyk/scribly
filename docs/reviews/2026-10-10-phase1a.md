## Findings

1. **high — R1 — `server/app/lesson/safe_expr.py:59`**
   The character/name allow-list permits floor division (`//`). SymPy 1.14's
   `EvaluateFalseTransformer.visit_BinOp` leaves unsupported operator subtrees
   untouched. Consequently `9^9^9^9//1` reaches eager power arithmetic despite
   `evaluate=False`, allowing a short expression to consume unbounded memory/CPU
   while preparing a calc or plot on the server. `1//0` also escapes as a raw
   `ZeroDivisionError`. A sentinel replacing `Expr.__pow__` proved the eager path
   without computing the enormous integer; the ordinary power tower never called it.
   **Suggested fix / applied:** validate the entire Python AST before SymPy;
   permit only supported arithmetic, numeric literals, names and one-argument
   allow-listed functions. Reject floor division, tuples, conditional/boolean
   expressions, arbitrary calls and excessive nesting before reaching `parse_expr`.

2. **high — R2 — `server/app/lesson/verify.py:24`**
   Non-finite expected values or tolerances pass verification: comparing against
   NaN is false, and infinite differences are not greater than infinite tolerance
   products. Pydantic accepts these floats, including infinity from JSON `1e999`.
   A valid calculation with expected NaN, +Infinity, -Infinity, or infinite relative
   tolerance was reported `ok=True`, violating verification before narration.
   **Suggested fix / applied:** require finite expected values and relative
   tolerances before evaluating/comparing; return a failed result so the existing
   pipeline marks and narrates the verification warning.

3. **med — R3 — `server/app/routes/lessons.py:55`**
   Logging `e.__cause__` prints Pydantic's raw template input values. A synthetic
   private marker in an unknown template parameter reached the log. The generic
   `logger.exception` branch at line 59 also includes raw exception messages.
   Currently this operates on local mock fixtures; reusing it for live generation
   would retain student/provider content in logs. Public SSE errors are sanitized.
   **Suggested fix:** log a safe event identifier, exception class and error count;
   omit raw causes and exception messages/tracebacks containing input values.
   **Unchanged:** strict expected-failure regression test preserves this finding.

4. **med — R4 — `server/app/lesson/verify.py:40`**
   A failed calculation does not get a spoken disclaimer if the input step already
   has `warning="unverified"`. The raw lesson model accepts this server-only flag;
   it also bypasses the narration word limit (`models.py:235`). A preflagged fixture
   with a wrong expected value streamed its confident original narration.
   **Suggested fix:** reject server-only fields at the raw input boundary, and
   append the disclaimer when absent independently of the visual warning flag.
   Preserve idempotence by checking the appended note, rather than the flag alone.
   **Unchanged:** strict expected-failure regression test preserves this finding.

5. **med — R5 — `server/app/lesson/models.py:21`**
   `populate_by_name=True` accepts a JSON vector with `from_` instead of `from`.
   The documented contract and `shared/lesson.schema.json` require `from` and
   reject `from_` as an additional property. Thus the same input has different
   validity depending on which contract consumer checks it.
   **Suggested fix:** require aliases at the JSON boundary (disable name-based
   validation there); update internal construction and regenerate/check schema
   and fixtures together if the model contract changes.
   **Unchanged:** strict expected-failure regression test preserves this finding.

6. **med — R6 — `server/app/lesson/models.py:297`**
   Every summary is exempt from checkpoint spacing, although the documentation
   exempts only a final summary. Six consecutive summary steps validate without
   any checkpoint, allowing teaching-rule enforcement to be bypassed.
   **Suggested fix:** exempt only the last step when it is a summary; count
   intermediate summaries toward the four-step run.
   **Unchanged:** strict expected-failure regression test preserves this finding.

7. **low — R7 — `web/e2e/smoke.spec.ts:3`**
   The only browser test checks the placeholder heading and console errors.
   `gauss-lesson.spec.ts` is absent, so AGENTS.md §8's end-to-end audio/drawing
   synchronization requirement cannot be verified. The renderer is planned for
   Phase 2; a passing smoke test is not evidence of Gauss playback.
   **Suggested fix:** add the real mock-mode Gauss playback test with the Phase 2
   renderer and deterministic test audio. Record this limitation until then.
   **Unchanged:** implementing a renderer is outside this review's fix scope.

8. **med — R8 — `server/app/lesson/models.py:37`**
   Drawing coordinates accept non-finite floats. A point with `x=Infinity` passes
   the complete pipeline, then Pydantic's JSON serialization emits `x:null`, which
   contradicts the generated schema's numeric coordinate and cannot be drawn.
   This remains distinct from R2's now-protected numerical verification boundary.
   **Suggested fix:** reject non-finite numbers in primitive and template parameter
   models, document the requirement, and check regenerated schema and all fixtures.
   **Unchanged:** strict expected-failure regression test preserves this finding.
